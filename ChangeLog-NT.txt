o Update 5 (2026.09.24)
  - Fixed MS-DOS diskcopy.dll dialog crashing Rufus
  - Fixed MS-DOS, FreeDOS, Syslinux, ReactOS, Grub, Grub4DOS options,
    as well as UEFI:NTFS formatting on Windows NT4.0
  - Fixed the debugging API "DebugActiveProcess"
    in case of crashes on Windows 2000 / NT 4.0
  - Fixed Fido ISO downloading (again)
  - Fixed VID:PID fetching with old / generic drivers
  - Fixed Windows NT4 font issues by switching to MS Shell Dlg
  - Fixed dropdown spacings on pre Windows Vista
  - Implemented a CI signature check for Powershell 7.2,
    improved detection, caching and security
  - Implemented proper networking detection; if WinINet can't reach
    rufus.ie despite detecting an active internet connection and TLS 1.2,
    networking won't be initialized
  - Implemented more dialogs for systems with no networking
  - Implemented extra checks against broken / incorrectly formatted
    volumes and invalid MBRs, Rufus-NT should no longer softlock
  - Implemented a check for whether USB drivers are installed on NT4
  - Implemented a "Diagnostics" option in the Log window, which saves 
    the log, the registry configuration and lists files in Rufus NT's appdata
  - Integrated grub-2.xx, syslinux 6.04 and grub4dos 0.4.x 
    (for systems with no internet connection)
  - Improved / fixed up networking prerequisites on Windows Vista
  - ext2/ext3 partitioning can be extremely slow on certain larger drives;
    added a warning before partitioning for USB drives larger than 16GB 
    (it took 25min for a 64GB USB3 drive, and 1min for a 8GB USB2 drive)
  - ext2/ext3 partition type detection should work correctly now
  - Since diskcopy.dll can't be embedded due to licensing rights, 
    a direct download link can be found in the Release notes
  - ... the downloaded file can be drag-and-dropped into the main window, 
        where Rufus-NT will check its SHA-256 hash and install it
  - Wrote a proper code audit, patch instructions and script for 
    bcdboot.exe, wimgapi.dll and ntapi.dll
  - Disabled unsupported languages on Windows XP / 2000 / NT4
  - Languages with special characters received additional localization
    files specifically for Windows NT4, to make them ASCII compatible
    ( and not appear as ugly black boxes :p )
